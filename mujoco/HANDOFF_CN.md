# MuJoCo运行包交接

更新时间：2026-10-23。范围：Nav / Climb / Push / Switch。主使用说明见 [README.md](README.md)。服务器部署目录：`/mnt/miaojigui/zyh/mujoco`；这个目录与已有的 `nav_skill*`、`push_skill`、`climb_skill`、`history` 分开维护。

## 1. 交付的是什么

交付可独立加载机器人、冻结Actor并运行MuJoCo仿真的代码和必要资产；没有训练数据/训练器、原始checkpoint、测试脚本/报告、既有录像、输出或真机SDK。Nav只有最初默认210维WBC，不含最近测试的315维Nav2。

| 技能 | 冻结产物 | 接口与用途 |
|---|---|---|
| Nav | `nav/policy/actor.pt` + `contract.json` | 210维观测、18维动作；原WBC底层速度/末端指令策略，目标导航是本地上层状态机 |
| Climb | `climb/policy/actor.pt` + `contract.json` | V1、第900轮；观测历史、关节顺序等由原契约约定 |
| Push | `push/policy/leg_actor.pt`、`arm_actor.pt` + `contract.json` | v212两Actor，来自model_199/model_255；原226维输入及IK/接触控制 |
| Switch | 无额外权重 | 直接从相邻三个技能加载上述Actor，必须保持目录相邻 |

`MANIFEST.json` 保存实际打包的模型SHA256、文件数量、范围和本机验证环境。`SHA256SUMS` 校验包内文件（不含SHA256SUMS自身），接收者在根目录运行 `sha256sum -c SHA256SUMS`。哈希用于核对身份/传输完整性，不证明策略效果。

原始Actor没有训练或改权重。本地对观测/动作、显式关节映射、执行器和停止/切换控制做了适配与开发；因此不能说整段控制完全等于原Isaac程序。机器人的质量/惯量/碰撞由XML与USD对应JSON profile共同构建，不应只看原XML中的旧参数。

## 2. 已完成的功能

### Nav

- 使用原始WBC：当前定位→朝向目标点→前进/途中修正→到点调整最终朝向→零命令连续停稳1秒→报告到达。
- 默认六臂目标零位，以受限PD和偏置力补偿保持；不逐步强写实际关节角。
- 到达后保持零底盘指令，继续物理并另记漂移。位置容差13cm、朝向约14.3°，外圈和停车内圈有迟滞。
- 默认skills参数：腿Kp/Kd=30/0.8，臂Kp=[40,40,40,20,20,20]、Kd全1；执行器目标延迟20ms。导航/策略50Hz、物理200Hz。

### Climb

- 保留V1/900原登台Actor；0～20cm高度参数同时影响实体障碍、地形输入和完成判定。
- 安全条件满足后平滑接入全身力矩QP，制动后用站姿过渡调整腿部弯曲程度，接近Nav静止姿态；实际关节角不强求逐轴相等。
- 停止姿态过渡结束后连续站稳1秒，再验证3秒；成功后可继续观察。机械臂沿用Climb约定姿态。
- 可选`--finish-mode ascent`复现原持续前行登台，不代表停稳。

### Push

- 原双Actor、关节映射、IK、接触分类与安全边界；本地新增平滑展开/接近和退出站立。
- 展开按原安全路点作五次平滑轨迹，最后接近锁存一次目标并平滑接入Actor残差，减少末端折返。
- 推箱达标后由QP支撑、沿检查过的逆路径收臂，六臂回零，连续站稳1秒并验证3秒。推箱阶段成功与完整退出成功分开记录。
- 碰撞检查包括箱子/地面/机身/腿/非相邻臂段。机身净空35mm、其他非相邻体2mm等检查仍保留；原PD和力矩限制未通过提速放宽。
- 初始承重沉降和Push参考姿态校准会在窗口运动开始前花费计算时间，不是程序卡死。

### Switch

- 同一个MjModel/MjData和延迟电机队列贯穿任务；运行中接管不瞬移机器人、不清零速度、不重置箱子。
- 状态机按任务列表执行：启动→技能→完成/停稳→下一技能入口检查/必要准备→约0.2秒完整电机命令平滑接管。
- Nav→Nav保留原策略历史；Nav→Push额外恢复独立Push的实际承重站姿，再启动Push。当前开发样本准备约4.96秒，不是硬编码保证时长。
- 各技能关节顺序不一：Nav/Push为FR/FL/RR/RL，Climb为FL/FR/RL/RR，运行接口按名字重排。
- 统一物理世界采用Push/Climb的USD质量/惯量、被动damping=0、frictionloss=0.01和Push自碰撞；Nav保留skills主动PD。单独Nav的被动阻力不同，单技能成功不能直接推导整链成功。

## 4. 已知问题与不支持的范围

1. **Push→Climb近距离仍未解决。** 活动箱踏步场景：平地0m、自由箱高20cm、高地40cm。推箱抵靠与收臂曾完成；默认约83cm起爬入口条件可能拒绝Push留下的更近位置。`--near-climb`显式实验在约56cm处准备后接管，四组对照均机身碰箱沿，前脚未先形成稳定箱顶支撑。没有证据说明“必须后退”，也没有验证通过的直接上箱方案。第二次爬高地及之后Nav未实际完成。
2. **Nav到点精度有限。** 最低有效速度较高，可能来回修正；现有容差13cm/14.3°，不是厘米级停靠。到达后是零速度指令保持，不是机身位置锁定，后续可能漂移。
3. **有限位仍有负荷问题。** 力矩饱和、关节速度/角度超限仍可能出现在原策略或切换阶段。速度主要监测，不是等价PhysX硬限速；MuJoCo软关节约束可少量穿透。应读实际报告，不能因没摔倒就认为安全。
4. **入口/场景不是任意的。** Push依赖指定箱子/方向/距离；Climb依赖沿+X和已知台面；Nav路点由人提供，无在线避障。Switch拒绝入口不满足是明确失败，不应删保护以制造通过。
5. **仿真真值与已知地图。** 未建立传感器/定位噪声及延迟、通信丢包/抖动、时钟对齐、地图配准、真实电机带宽、温度/电池/柔性模型。已有20ms是命令延迟假设，并非传感器延迟或实测硬件值。
6. **引擎差异。** MuJoCo/PhysX接触求解、摩擦组合、驱动/速度约束和随机化不完全相同；相同seed不等价于相同轨迹。
7. **Switch不是完整技能SDK。** 已有可读任务列表和状态机，但路径规划、任意起始姿态的自动恢复、故障恢复和所有技能对的泛化未交付。`--near-climb`只是保留的失败研究入口。
8. **本包未带训练/真机功能。** 不含Isaac、完整USD工程、CAN/UDP/ROS节点、Go2/PiPER SDK或硬件急停。不能拿这份包直接发电机命令到实机。

## 5. 文件职责与安全修改顺序

| 需求 | 查看位置 |
|---|---|
| Nav命令行和回合 | `nav/navigate.py`；`play.py`是底层速度回放且被导航复用，不可删 |
| Nav目标跟踪配置/状态/决策 | `nav/navigation.py`：NavConfig、NavState、NavSkill |
| Nav执行增益/启动 | `nav/control_profiles.py`；映射/历史/电机在`nav/bridge.py` |
| Climb任务/地图/物理适配 | `climb/play.py`、`bridge.py`、`policy/contract.json` |
| Climb停止控制 | `climb/stop.py`：StopConfig、WholeBodyQP、StopController |
| Push场景/接口 | `push/model.py`、`bridge.py`；Actor加载在`policy_loader.py` |
| Push展开/对准 | `push/timing.py`、`controller/approach.py`；其余controller保留原IK/几何/接触控制 |
| Push退出/碰撞/站立 | `push/finish.py`、`balance.py`、`motor.py` |
| Switch配置层 | `switch/plans.py`（路线列表）、`staircase.py`（已知踏步地图） |
| Switch状态/路由层 | `switch/machine.py`：startup、prepare、blend、run、complete及入口条件 |
| Switch执行层 | `switch/runtime.py`（唯一世界、命令队列、关节重排）；`plugins.py`隔离同名模块 |
| Switch特定准备 | `push_entry.py`为当前平地Push准备；`climb_entry.py`只供未通过的近距离实验 |

先改场景/上层目标，再调控制配置；更换Actor前核对输入维度、历史排列、关节顺序、缩放、前一动作定义和执行器合同。不要把315维Nav2塞进当前210维接口。若迁移资产，要一起保留XML、assets、两份profile与许可证；只拷贝XML不够。

Push安全路点JSON仍位于source下的原相对路径，这是两处运行代码直接读取的必要配置；其余source快照被排除。不得为了“清理source”删掉此文件。所有路径依赖`__file__`而非本机绝对路径；可搬动整个mujoco目录，但四技能相对布局要保留。

## 6. 接收者怎么继续

1. 校验SHA256，准备独立MuJoCo环境；先确认Torch/CUDA与MuJoCo版本，见根README。服务器原有Isaac环境保持不动。
2. 先跑四个根README中的headless命令，再开GUI或EGL录像。查看任务报告和持续保持结果，而非只看视频或进程退出码。
3. 对本次要交付的目标/高度/距离/seed/延迟建立同版本基线。记录质量、摩擦、限矩、超速/角度、碰撞、目标误差和停止漂移。
4. 要继续箱子踏步任务，先隔离Push结束后的脚位/重心/距离与Climb原训练起步分布。保持碰撞和负荷检查，验证前脚上箱支撑时序；不要只盲调速度或取消入口检查。
5. 正式跨仿真或实机前另行开展同源对照、多seed/物理条件测试、传感器/执行链标定与分级实机验证。本包不授予实机放行。
