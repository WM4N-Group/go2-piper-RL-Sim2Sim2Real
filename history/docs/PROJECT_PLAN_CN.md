# GO2-PIPER 项目计划

更新日期：2026-10-15（NAV→CLIMB→NAV入口及独立完成判定）

## 目标

建立可复现、可审计的 GO2-PIPER 底层技能闭环：平地导航、指定末端推箱和低台攀爬，以安全、分级的 Sim2Real 为最终目标。MuJoCo 是独立风险筛查工具，不是必须与 Isaac 逐步一致的部署目标。

## Re-NAV 分工与跨组交付

Re-NAV 有三个并行方向：本组负责 GO2-PIPER 底层技能训练、优化和实机部署；世界模型组已在PIPER/Isaac中以冻结旧技能和规则Oracle开展连续任务与后果模型研究，ARX5/MuJoCo作为历史结构参考；reachability组在固定技能与过渡版本上研究接管资格及技能选择。现有实物条件只有 PIPER 机械臂，因此世界模型研究成果的实机迁移也依赖可用的 PIPER 技能。

本组应向其他两组交付可版本化的 GO2-PIPER 技能，而不只是权重文件：每项技能包含任务语义、观测/动作和关节顺序契约、匹配控制器与资产、checkpoint/actor 哈希、独立评估结果及适用边界。世界模型组旧PIPER整链与新PUSH v212必须分别绑定来源；ARX5策略不能作为PIPER策略；reachability 组可先使用明确标注边界的仿真参考策略，不得将其当作实机许可。世界模型若需要低板或架桥动作，普通 PUSH 的验收也不能代替 PUSH-LOW。

## 系统结构

```text
PIPER 训练资产与任务
        -> PPO 策略 / PUSH 姿态 IK
        -> Isaac 原生验收
        -> MuJoCo 来源匹配的任务级风险筛查与失败归因
        -> 实物参数标定与安全控制器
        -> 分级实机验证
```

技能边界约束：保留各技能已验证的输入合同、起止语义及执行模式，姿态转换与承重准备单列为过渡段。NAV原交接默认末端目标为(0.5,0,0.4)；修改目标或在活动期持续改写18轴输出必须显式声明版本与受保护执行模式。先确认原技能在当前实际限矩/PD/延迟下的工作域，随后验证过渡进入该工作域；不以权重未变代替行为合同保留。当前审计结论见CLIMB页，原安全门禁与真实动作历史保持。

技能职责：

- NAV：平地目标位置与朝向控制。
- PUSH：以指定手部推面推动自由箱体；当前v212为226维输入、19维输出，独立冻结12腿输出加6臂残差/1臂速度与配套IK。完整契约见PUSH页，旧12维actor调用不适用。
- CLIMB：冻结actor与受约束控制器配合，逐脚登上20cm固定台面；四足承重停稳后前脚逐只展开，再最后前移重心达到舒展稳定姿态。之后到任务目标点由NAV负责，技能切换另行验证。

## 安装假设

GO2 与 PIPER 在训练和 MuJoCo 中按刚性固定安装建模：PIPER 是 `base_link` 的子体，没有
安装自由度或独立悬挂。实际运行的 MuJoCo profile 使用相对平移 `(0, 0, 0.07 m)`、单位旋转；
原始 XML 的 `0.06 m` 仅是被 profile 覆盖前的源值。任何实物安装偏差都会同时改变 FK、
碰撞距离、重力补偿、质心、接触反作用和 Sim2Real 初态，必须作为受控模型版本更新。

## 验收标准

| 阶段 | 条件 |
| --- | --- |
| 原生 Isaac | 两组独立 32 回合，每组至少 30 成功，0终态缺失；其余正常终止失败须完整分类 |
| MuJoCo 风险筛查 | 沿用两组独立 32 回合、每组至少 30 成功及相同成功/安全判据报告结果；未通过必须定位失败机制和实机相关性，不作为逐步物理量一致性门槛 |
| 控制来源 | checkpoint、actor、任务源码、控制器、profile、资产和数值后端均可追溯 |
| 实机 | 安全链路与标定完成后，按悬空、支架、平地、接触的顺序逐级验证 |

统计口径：完整成功、正常失败（含任务超时）、已启动但缺失终态、未运行分别列出。每组32是预先固定的总起点分母；0缺失不等于要求32/32成功，提前停止后的未运行也不能记成功或混作缺失。种子在任何调参/开发筛查中用过后，就不能再作为最终未用验收种子。

PUSH 的成功要求指定手部接触、目标误差小于 `0.12 m`、箱体速度小于 `0.08 m/s` 并持续 `0.5 s`。CLIMB要求四足位于安全顶面并真实承重、姿态和速度合格，前脚逐只展开及最终重心调整完成，连续停稳至少`1 s`。这是目标验收契约；历史阶段结果来自离线终态核验；独立完成判定模块已接入连续物理执行器，采用连续3s停稳，已有同控制器3/3原起点整链开发成功，制动参考连续性修复版正在回归；仍非正式未用起点或效率验收，具体证据见CLIMB页。不得通过降低碰撞、姿态或停稳门槛提升结果。

MuJoCo 未通过不等于策略在实机必然失败，但未解释的摔倒、碰撞、超限、停止失效或任务失败也不能被跳过。先核对观测/动作接口和资产来源，再用任务时序与物理量判断风险是否可能出现在实机；可信或未排除的安全风险阻止相应实机阶段。完成两端批量验收、风险归因和独立实机安全链路验证后，才可逐级推进；不要求 Isaac 与 MuJoCo 的首步接触力或轨迹完全重合。PUSH-LOW 训练及实机接触仍暂停，诊断报告不构成验收。

先保留成功路径、提高鲁棒性，再减少冗余等待和规划耗时。最终候选的原起点与完成窗口须在测试前固定并写入报告；当前尚未达到12秒/24秒验收，不以延长诊断窗口解决效率要求。报告分别列出登台、展开、最终稳定完成时间，以及完整成功/失败/终态缺失，不能只报阶段平均时间。

### 统一交接合同与控制候选

1. **固定共同物理域。** 一个场景、一份机器人状态、持续物理时钟和统一执行器实例。启动前核对资产、自碰、质量/摩擦、PD、动作缩放、默认角和延迟；契约不一致就显式拒绝或另立候选，切换时不能暗改增益/材质使某技能“恢复”。新v212先在其1kg/0.15域接NAV；世界模型旧4/5kg、桥箱/低板域另列，不迁移成功率。
2. **保存真正下发的承重命令。** 将raw actor输出、组合18轴输入、处理后的PD目标、延迟队列及实际力矩分开记录。切换首条目标从上一实际命令接续，保留延迟/滤波状态；随后按速度和加速度约束过渡。不要以当前q简单替换承重目标，也不无条件清零上一动作和历史。若用力矩反推参考，仅作核验/有界候选，需覆盖阻尼、延迟、饱和和补偿，不能默认反算等价。
3. **为每种技能编写明确适配器。** NAV原生210/18；PUSH v212保留双checkpoint、独立冻结腿hook、226/19映射和全部控制器；CLIMB保留304输入与阶段程序。各自维护按本版顺序构造的实测观测历史，记录有效长度；不复制别的技能张量。原始策略输出不直接互相插值。新增接管初始化函数只初始化本技能逻辑与目标，不调用整场景reset，不注入stage-bank物理状态。
4. **承重稳定与臂运动协调。** 状态流程为 `ACTIVE → DECELERATE/UNLOAD → CAPTURE → STABILIZE → READY → NEXT_ACTIVE`，另有 `FAILED`；并非每条边都需卸载。捕获门槛、稳定动作域、最终准入分别声明。先从真实载荷和已下发目标初始化支撑保持，再在原净空/力矩/支撑约束下移动臂；保持失效时必须明确失败，不能无限等。稳定控制和安全退出均为待验证候选，零速度、锁臂、abstain本身不称安全动作。
5. **定义真正的决策时刻。** 发布 `transition_started`、`transition_ready(t_plus, s_plus)`、`skill_started`、`transition_failed(reason)`。对NAV→PUSH，t_plus位于过渡完成、PUSH首个接近动作之前；不能复用后续safe_approach_complete/motion_ready作为t_plus。快/慢技能选择也在此前完成，并按各技能入口分别验可接入性。等待后状态变化需要刷新资格和时间预算；reachability不授权时由经验证的过渡控制保持或退出，无可用动作则不开放在线接管。
6. **对象和坐标显式绑定。** 第二PUSH用object_id、任务坐标变换及新目标重绑定，验证机器人与所有箱物理状态不变；只清理旧箱的逻辑状态，不重置执行器历史。记录非手预接触和选箱前漂移。先检查目标/路线与静态场景是否可行，再归因切换控制。

50Hz最少记录切换前后全窗口：before状态、请求/处理/实际执行目标、关节速度/力矩、四足受力、支撑、腾空、竖直速度、净空、接触合力、合法手接触、各门禁值及最长连续通过时间。执行器饱和含初始化；切换短窗口另记录物理子步力矩以检查隐藏峰值，控制步统计不冒充子步保证。报告总起点数、NAV失败、过渡失败、技能失败、成功与缺失，不能只用到达t_plus的幸存者作整链分母；原速视频、无reset和SHA核验一并交付。

本组负责过渡控制器、可调用技能适配器、稳定/退出动作与物理验证；reachability组消费固定t_plus状态，研究放行/等待/固定技能选择及独立校准；world-model组负责Oracle场景/意图、因果数据与后果预测，模型继续shadow。caller、技能、目标或几何变化均进入版本条件，未进入阶段的下游标签保持删失，不把控制改进归因于模型收益。

## 训练与控制原则

- 冻结通过验收的 actor；任何优化在新 run、独立 checkpoint 和独立报告中进行。
- PUSH 机械臂采用受限 IK，训练和运行时都必须包含关节限位、速度限制、净空与合法接触约束。
- CLIMB 训练需要接触课程、左右对称、动作平滑、关节速度/加速度、冲击与能耗约束，不能只优化终态成功。
- 先对质量、质心、惯量、安装变换、关节零位、延迟、FK/Jacobian、重力与观测逐项对齐，再讨论接触迁移。
- 实机数据仅以只读状态和受控试验采集方式进入标定与训练回灌。

安全接近路径必须经过动态验证；路径点数量不是安全判据。短路径仍须保留实际到位、碰撞、净空、力矩与合法接触门禁，并重新验证成功率。静态FK、单条录像或关闭碰撞后的成功不构成安全证据。

## 交付物

- 冻结策略包与完整 checkpoint；
- 训练、评估、导出和回放入口；
- PIPER 资产、碰撞与惯量 profile；
- 每项候选的 SHA-256、评估报告和失败原因统计；
- 分级实机控制与安全验证记录。
