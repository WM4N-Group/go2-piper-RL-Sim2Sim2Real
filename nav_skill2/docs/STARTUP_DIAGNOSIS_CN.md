# Nav2 起步与平台期诊断：2026-10-22

本次检查固定使用V3 `model_500.pt`，SHA256 `f69dc22ccc9d21f15f7c3a7d314070f503a7a93c19de7fd2997aca956169ff0c`。正在运行的4096环境训练未停止、未改参数。Climb/Push/旧Nav及共享资产不修改。

## 为什么初始会下落

原先按默认q的真实足底FK计算根高0.32550m，已经接近地面；不是简单地从很高位置生成。但默认关节实际角等于PD目标，起始弹簧力矩为0，尚未建立负重支撑。再叠加策略第一步的大残差，出现机身下沉、反弹和机械臂受冲击。原来的0.4秒启动和0.6秒指令渐变只处理速度，不限制第一步关节目标。

对照过0.8秒和2秒单独动作渐入，都不足以完全解决原来的初始压缩，因此没有把单独渐入宣称为最终方案。

## 当前代码改法

1. 一次性用每个环境自身的质量、摩擦、PD、延迟与真实重力，在默认目标下运行3秒物理，建立承重平衡。
2. 缓存真实关节角、机身高度和姿态。reset恢复缓存并清零速度；保留原默认PD目标，因此承重所需的位置误差已经存在。姿态与根高来自同一次物理，不用降低根高配默认q的方式制造穿地。
3. 策略腿部残差在前2秒按五次曲线渐入。探索动作也一起渐入，实际执行动作写入历史与动作变化成本。没有焊接机身、强锁腿、提高限矩或持续腿部重力补偿。
4. 预计算若未稳定就报错：机身倾斜>0.15rad、根线速度>0.05m/s、关节速度>0.3rad/s，或高度<0.2m、支撑脚不足3只、机身/臂非法接触。这里的三足检查只用于缓存静态初始化状态，**不是行走步态要求**。

参数：`configs/nav.json` 的 `task.reset_settle_seconds=3.0`、`task.startup_action_ramp_seconds=2.0`。实现：`nav_skill2_env.py` 的 `_prepare_settled_reset`、`_reset_idx`、`_pre_physics_step`；曲线在 `commands.py:startup_action_gain`。

旧checkpoint两个字段缺省0，保持原合同；play提供显式覆盖并在report记录。当前长训练沿用旧内存配置，不会自动变成新配置。新训练建议从头开始；续训恢复checkpoint的配置。

CPU与GPU分别42环境：7种速度指令×确定性/带原训练探索噪声×3个延迟（0/2/4个5ms物理步）。无相机，不自动reset，固定500轮策略。新初始化也做同规模GPU对照。它们是短工程诊断，不是32回合正式验收。

## 平台期不只是速度太低

相同延迟成对对照，激活段使用存活样本计算：

- GPU倒退指令−0.25：确定性实际约−0.059m/s，带探索约−0.312m/s。
- GPU左转指令+0.35：确定性实际约+0.198rad/s，带探索约+0.653rad/s。
- GPU右转指令−0.35：确定性实际约−0.291rad/s，带探索约−0.661rad/s；确定性3例里2例失败。
- CPU同样有倒退弱、确定性转向失稳；右转3例均失败。首个失败帧的机身/机械臂非法接触力超阈值，不能归因于MuJoCo或只归因GPU/CPU。

说明策略依赖训练探索噪声来换脚，均值策略尚不可靠。当前超速成本有余量，方向响应正奖励已封顶，较大的探索仍可能换来更高响应。下一步应单独处理探索退火与确定性动作评估；不能把训练奖励或单条视频作为已经训练好的证据。本次没有未经验证地改奖励、AMP或探索参数。
