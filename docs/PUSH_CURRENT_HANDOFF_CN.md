## 既有远端复现命令

先按[总交接的进程检查](AGENT_HANDOFF_CN.md#环境与首次核对)确认GPU可用，同时检查 `evaluate_residual_push.py` 进程；不要重复启动。下面命令在**既有远端**执行，重跑已用seed3701/8环境并录env0，使用新目录保存报告。不能擅自改成1环境并声称逐值复现同一视频。

```bash
PUSH_ROOT=/path/to/artifacts/go2-piper/sim2sim-current-20261008-a
PUSH_SOURCE="$PUSH_ROOT/push-direct-approach-v212/train"
PUSH_GEOMETRY="$PUSH_ROOT/runtime-push-detour-v1/mujoco"
PUSH_CHECKPOINT="$PUSH_ROOT/push-warmstart-train-v205/train/logs/rsl_rl/go2_piper_box_push_hybrid/2026-10-13_05-16-06_full_light_train_8052/model_255.pt"
PUSH_GPU=0  # 改为本次核对空闲的物理GPU编号
PUSH_OUT=$(mktemp -d "$PUSH_ROOT/push-v212-recipient-XXXXXXXX")
cd "$PUSH_SOURCE"
CUDA_VISIBLE_DEVICES="$PUSH_GPU" \
PYTHONPATH="$PUSH_SOURCE/source/LeggedManip_Lab:$PUSH_GEOMETRY" \
PIPER_SOURCE_ROOT="$PUSH_SOURCE" PYTHONUNBUFFERED=1 \
/path/to/bin/isaac-python scripts/evaluate_residual_push.py \
  --task GO2-PIPER-Box-Push-Tracking-Play \
  --checkpoint "$PUSH_CHECKPOINT" --num_envs 8 --episodes-per-env 1 \
  --steps 2400 --episode-length-s 48 --headless --device cuda:0 --seed 3701 \
  --push-ik-clearance-minimum 0.1 --push-hand-pitch 1.0 --push-height-offset 0.0 \
  --push-contact-memory-s 0.10 --push-leg-release-ramp-s 0.7 --push-leg-contact-ramp-s 0.2 \
  --push-press-on-legal-contact --push-forward-command-gain 2.0 --press-depth 0.08 \
  --push-ik-joint-limit-solve --push-goal-hold-pose --push-stop-distance 0.11 \
  --push-ik-orientation-weight 0.5 --push-contact-gap-slowdown-start 0.0 \
  --failure-history-steps 128 --box-height 0.2 --push-distance 0.60 \
  --box-mass 1 --box-friction .15 --push-approach-height-gate --push-joint4-floor 0.8 \
  --push-geometry-root "$PUSH_GEOMETRY" --push-geometry-minimum 0.035 \
  --push-ik-height-weight 2.0 --output-json "$PUSH_OUT/report.json" \
  --video-path "$PUSH_OUT/full-push-env0-original-speed.mp4"
```

入口自动启用录像所需相机；去掉 `--video-path` 可只做同批物理评估。env0终止后录像停止，其他环境继续完成配额；不要剪掉失败段或拼接reset。成功不能只看进程退出码：检查 `report.json` 的 `successful_episodes`、`completed_episodes`、`incomplete_episodes`、`termination_reasons`、`physical_safety_control_samples` 和 `startup-physics.json`。原8/8视频为16.00s、1280×720、25fps、400帧。

跨机器迁移须处理 `scripts/rsl_rl/safe_retraining.py` 中硬编码的 `ROOT`、`LEG_CHECKPOINT` 和资产路径；设置命令行 `--push-geometry-root` 并不足以覆盖该文件中的ROOT。用新副本修改路径，保存变更及新哈希并回归，不改原v212快照。本版Isaac环境内还需要匹配的MuJoCo几何查询依赖；这不表示已在MuJoCo中运行完整动力学。环境参考版本见总交接，不向系统Python安装依赖。

## 控制契约与上层接入

模型输入为226维，输出为19维。必须由本版 `scripts/evaluate_residual_push.py` 加载 `actor_state_dict`，并调用同版 `scripts/rsl_rl/safe_retraining.py::install_frozen_legs`；该hook从model199独立计算前12维腿输出，model255负责后7维。**直接运行model255的原始前12维会绕过冻结腿契约。** 不可使用旧226→12或18维部署入口。

| 层级 | 接入必须保留的约定 |
| --- | --- |
| 观测 | 使用快照中的Tracking任务观测构造、项顺序、历史、归一化与reset；226这个总维度不足以独立重建输入 |
| 动作 | 前12维冻结腿；`12:18`为6轴臂残差 `0.20*tanh`；第18维经sigmoid为臂速度比例；这19维不是直接下发的19个关节位置 |
| 执行 | `mdp/residual_push_actions.py` → `BoxPushLegAction`配套控制器 → 原PD/延迟；保留关节重排、默认角、限位、实际到位、速度和真实接触判定 |
| 起步/平滑 | reset按实际关节状态初始化目标；残差与速度1s三次平滑启用，接触面实际准备好前残差限制±0.02rad；补偿后的最终PD目标60ms滤波 |
| 安全 | 原生本体自碰开启；实际机械臂—机身几何表面净空<35mm立即失败；臂力矩/限值≥0.98立即失败，包括初始化；保留原碰撞、姿态、非法手接触及停稳门禁 |
| 完成 | 使用 `box_settled` 且无同时发生的失败项，记录最终误差和停稳时长；不要仅以手已碰箱、路径结束或箱移动过作为完成 |
| 失败/超时 | 非法接触、姿态/碰撞/净空/力矩失败均上报失败；time_out及终态缺失不能转成成功；具体退出后的控制接管需单独设计验证 |

35mm几何查询覆盖 `link1…link6` 对 `base_link` 的凸包表面，并非所有机械臂/腿/箱体配对；原生碰撞与合法接触门禁仍必需。不能把该净空统计写成“所有部位无碰撞”。自碰开启是本版评估事实；历史model199整套PUSH任务曾关闭本体自碰，不能沿用它的旧安全结论。

尚未交付经过验证的NAV→PUSH→NAV统一SDK。接收组先复现上述reset场景，再与底层组对齐调用起点、状态/历史缓冲、首命令连续性、目标坐标、终止信号和安全退出。任意NAV停靠姿态不得直接假定等价于任务reset；PUSH完成只表示本次箱目标与停稳，不包含后续导航。
