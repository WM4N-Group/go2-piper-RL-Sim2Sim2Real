# GO2-PIPER 固定安装与 Sim2Real 标定

模型说明：2026-09-22；交接核对：2026-10-16。当前优先技能平稳切换，方向与验收见[项目计划](PROJECT_PLAN_CN.md)；MuJoCo尚处诊断阶段。实机接入／标定按main的2026-10-19安排启动，当前尚无实机执行结果；以下步骤按既定分级条件实施并记录实际结果。

## 目的

本文定义当前 GO2-PIPER 仿真中的机械连接假设，以及实物安装后必须测量、更新和验证的
参数。PUSH、CLIMB 的碰撞净空、末端 IK、重力补偿和底座反作用均依赖该连接模型。

## 仿真连接模型

PIPER 不是独立机器人，也没有安装关节、悬挂或柔性支撑。它是 Go2 `base_link` 的刚性
子体：

```text
Go2 floating base
└── base_link
    └── Piper (rigid mount)
        └── link1 ... link6
            └── end_effector
```

Go2 与 PIPER 共享一个 floating base、同一动力学求解器和同一底座状态。PIPER 的 `joint1`
至 `joint6` 是该组合模型中仅有的机械臂自由度。

## 运行时安装变换

在 `mujoco/robots/go2_piper/go2piper.xml` 中，原始 `Piper` body 相对 `base_link` 的位姿是：

```text
translation = (0.0, 0.0, 0.06 m)
rotation    = (1.0, 0.0, 0.0, 0.0)
```

但 PIPER runtime 会通过 `mujoco/deploy/piper_robot_profile.json` 调用 profile 覆盖，实际
运行的名义变换是：

$$
T_{\mathrm{base\_link}\leftarrow\mathrm{Piper}} =
\begin{bmatrix}
I_3 & (0, 0, 0.07)^\mathsf{T} \\
0 & 1
\end{bmatrix}.
$$

即：

```text
x = 0.0 m
y = 0.0 m
z = +0.07 m
roll = pitch = yaw = 0 deg
```

实物安装和所有 Sim2Real 验证必须以`0.07 m` profile值为当前仿真基线；XML的`0.06 m`
只是不经 profile 覆盖时的源值。

## 质量与反作用

安装座body `Piper`的profile质量约为`1.02 kg`（不是整条机械臂或组合机器人总质量），并且完整机械臂链的质量、质心与惯量
都参与同一 Go2 floating base 的动力学。机械臂运动会对 Go2 底座产生反作用，因此安装变换
的偏差会同时改变：

- 末端 FK 和 PUSH 接触点；
- `link6` 到机身、头部和前腿的碰撞净空；
- 重力补偿与关节目标；
- 组合系统的总质量、质心、惯量和底座姿态响应；
- Isaac 与 MuJoCo 的初态、接触和安全 waypoint。

## 实物安装要求

1. 用刚性金属转接板和可靠紧固件将 PIPER 基座固定在 Go2 主机身对应 `base_link` 的位置。
2. 不得引入安装自由度、明显柔性支撑、橡胶隔振件或未建模的悬挂结构。
3. 安装时保持 PIPER 基座坐标系与 Go2 `base_link` 坐标系同向，避免额外 roll、pitch、yaw。
4. 将安装板、螺栓、线缆固定件、保护壳、额外传感器和任何外挂件计入组合质量与质心。
5. 线缆必须留有运动余量且不得进入臂链、腿部或碰撞包络；线缆接触不是当前仿真模型的一
   部分，必须通过硬件设计消除。

## 实物标定与模型回写

实际安装后必须测量：

$$
T_{\mathrm{base\_link}\leftarrow\mathrm{Piper}} =
[x, y, z, roll, pitch, yaw].
$$

建议先达到以下工程精度；这些是待验证的工程目标，尚无实物测量记录证明已达到：

| 参数 | 建议目标 |
| --- | --- |
| 平移x/y/z | 误差不超过2mm |
| 旋转roll/pitch/yaw | 误差不超过1deg |
| 安装后总质量 | 实测 |
| 全局质心 | 实测或受控标定 |
| 碰撞包络 | 实物全范围检查 |

如果实际值与名义值不同，必须以新的受控模型版本更新：

1. Isaac `source/LeggedManip_Lab/LeggedManip_Lab/assets/go2_piper/go2_piper.usd`、引用的`configuration/`层与关联profile；
2. MuJoCo `go2piper.xml` 和 `piper_robot_profile.json`；
3. `piper_collision_profile.json`；
4. PUSH IK 的安全 waypoint、净空阈值和评估报告；
5. 需要时重新训练并重新执行 Isaac/MuJoCo 两组 32 回合验收。

不得只改其中一个后端，也不得沿用旧 checkpoint 的安全结论。

## 低层控制 Sim2Real 标定

低层策略的标定目标是：对同一状态和动作命令，实物产生的关节、末端、底座和接触响应应与
训练/验证模型在可接受误差内一致。当前项目应按以下五类参数组织标定结果，每次修改都要
记录时间、设备、测量方法、原始数据、拟合值和适用的模型版本。

### 1. 几何与坐标系

- 标定上文定义的六自由度安装变换；
- 标定 Go2 `base_link`、PIPER 基座、末端、箱体和地面的坐标系定义；
- 以实测外参更新 USD、MuJoCo XML/profile、collision profile 和 IK waypoint；
- 通过多组已知关节姿态验证末端 FK 位置与姿态误差。

### 2. 关节与执行器

- 核对 Go2 与 PIPER 每个关节的零位、正方向、可用范围和软限位；
- 测量位置目标到实际关节位置的静态偏差、速度上限、死区、回差和饱和；
- 对每个关节拟合有效Kp、Kd、摩擦、armature和力矩/电流限制；
- 对臂链和腿链分别记录控制频率、命令延迟、状态延迟及抖动分布。

### 3. 组合动力学

- 测量安装后的总质量、全局质心和惯量，而不是仅使用 Go2 与 PIPER 说明书质量相加；
- 将安装板、螺栓、线缆、保护壳和外挂传感器纳入质量与质心；
- 在悬空和支架条件下执行受控 arm trajectory，记录底座位移、姿态、角速度和足端载荷；
- 用这些轨迹校正组合系统的重力补偿、底座反作用和关节阻尼模型。

### 4. 时间与状态一致性

- 统一 Go2 状态、PIPER 状态、控制命令和安全监控的时间戳；
- 测量从状态采样到命令生效的总延迟，以及 Go2/PIPER 两条控制链的相对延迟；
- 在仿真中使用相同控制周期、延迟队列和命令保持方式；
- 对连续技能切换保留上一技能的关节位置、速度和 actuator history，不得只对齐 reset 初态。

### 5. 碰撞与接触

- 实测 PIPER `link2..link6`、末端、Go2 机身、头部、前腿和安装板的碰撞包络；
- 验证当前 collision profile 覆盖实物外形，并记录可能未建模的线缆和保护结构；
- 标定箱体质量、尺寸、摩擦、地面摩擦和接触阈值；
- 对每个安全 waypoint 以真实 PD、延迟和重力补偿执行，记录动态最小净空和首次违规 pair。

## 标定验收顺序

```text
安装外参
    -> 关节零位/方向/限位
    -> 单关节执行器与延迟
    -> 总质量/质心/惯量
    -> 悬空 arm trajectory
    -> 支架 SAFE_APPROACH / CLEAR_ARM
    -> 平地底座反作用
    -> 低风险接触
```

每个阶段通过后才进入下一阶段。任何阶段与仿真差异超过可接受范围时，应先回写模型并重新
验证，而不是通过放宽碰撞、终止或成功条件掩盖差异。

## 分级硬件验证

在接触任务前按以下顺序验证：

1. 断电检查安装刚度、紧固件、线缆和机械极限；
2. 只读状态采集，核对 Go2/PIPER 坐标、零位、方向和时间戳；
3. 悬空低增益关节运动，验证 FK、重力补偿和无碰撞轨迹；
4. 支架状态下执行 SAFE_APPROACH 与 CLEAR_ARM；
5. 平地低速、无箱体动作，检查底座反作用和姿态响应；
6. 仅在安全轨迹和双仿真验收通过后，进入低风险箱体接触。

当前项目未包含真实 Go2/PIPER 硬件控制 SDK 或安全控制节点。本文件描述的是机械与动力学
一致性要求，不替代急停、供电隔离、通信超时和驱动器故障处理。

移交时提供模型/profile版本与SHA256、安装测量记录、设备型号/固件、坐标和关节映射、限制与延迟测量及安全链路责任人；目前缺少的实物资料应标“待测/未实现”。固定安装假设和名义参数可从[机器人profile](../mujoco/deploy/piper_robot_profile.json)追溯，候选实际使用的资产哈希仍以各技能报告为准。更换模型后须重新核验，不能用本页名义安装值推断某一候选已经对齐实物。
